# Exastro IT Automation 2.10.1

## 機能追加

### AIアシスタントでのConductor操作とパラメータ集の検索条件の保存（[#3116](https://github.com/exastro-suite/exastro-it-automation/issues/3116), [#3117](https://github.com/exastro-suite/exastro-it-automation/issues/3117)）

AIアシスタントで、Conductorの作成・実行、定期実行の設定、およびパラメータ集の検索条件の保存（プリセット登録）が行えるようになりました。\
これにより、Exastro IT Automationの知見が少ない担当者でも、自然言語での指示によって、複雑なフローのジョブや定期実行の設定、時系列ごとの構成表示が可能なパラメータ集を扱えるようになります。


## 改善

### 脆弱性の見直し（[#3113](https://github.com/exastro-suite/exastro-it-automation/issues/3113)）

脆弱性という観点から、各モジュールのアップデートに関する見直しとアプリケーションロジックの見直しを行いました。

この脆弱性の対策のため、次の仕様の変更が含まれています
- Webhookの通知で通知先URLに許可設定されていないプライベートIPアドレス帯のホストを指定することが禁止されます。これは既に登録済みのWebhook設定も同様に通知時にエラーとなります。(Teams,ServiceNowの通知先URLについても同様のチェックが行われます)
- 作成されたメニュー（パラメータシート）の「リンク」カラムでは、javascriptコードの実行が禁止されます。
- HTTPレスポンスに、次のセキュリティヘッダを追加しました。
  - **Strict-Transport-Security(HSTS、1年)**: HTTPSでアクセスした場合のみ付与します。ブラウザは1年間、そのホストへHTTPSでのみ接続します。サーバ証明書が期限切れや不備のときは、警告を回避してアクセスすることができなくなるため、証明書の有効期限にご注意ください。
  - **X-Frame-Options / Content-Security-Policy(frame-ancestors)**: 別のオリジンのページからのiframe埋め込みができなくなりました。同一オリジン内の表示には影響しません。
  - **X-Content-Type-Options / Referrer-Policy**: Content-Typeを正しく返すことを前提にした設定です。別オリジンへの遷移時は、Refererにオリジンのみが送られます。
  - **Content-Security-Policy-Report-Only**: 動作確認用です。画面の動作には影響しませんが、ブラウザのコンソールに警告が出る場合があります。
- exastro-docker-composeの接続方式の既定値をHTTPからHTTPSに変更しました。HTTPでの接続も引き続き利用できます。
  - **既存のHTTP環境をHTTPのまま使う場合**: アップグレード前に、次のいずれかを実施してください。実施しない場合、アップグレード後はHTTPSで起動しようとするため、サーバ証明書がないとplatform-authが起動に失敗します。
    - `.env` に `EXASTRO_HTTPS=false` を追記する
    - `setup.sh` で `.env` を作り直し、プロンプトでURLに `http://` から始まる値を入力する（`EXASTRO_HTTPS=false` が追加されます）
- 以下のAPIで、権限のチェックを行うようにしました。

    | API | メソッド | 利用できるユーザー |
    |---|---|---|
    | `/api/{organization_id}/platform/setting` | GET、PATCH | オーガナイゼーションの設定を更新する権限を持つユーザー |
    | `/api/{organization_id}/platform/workspaces/{workspace_id}/settings/notifications` | GET | ワークスペースのメンバー |
    | `/api/{organization_id}/platform/workspaces/{workspace_id}/notifications` | POST | ワークスペースのメンバー |
    | `/api/{organization_id}/platform/workspaces/{workspace_id}/conversations`<br>`/api/{organization_id}/platform/workspaces/{workspace_id}/lessons` | すべて | ワークスペースのメンバー |

    ```{warning}
    これまで権限のないユーザーでも実行できていたAPIが、権限不足で実行できなくなります。\
    APIを直接呼び出している場合は、利用するユーザーのロールを見直してください。
    ```





### GitLabの最新バージョンへの対応（[#3115](https://github.com/exastro-suite/exastro-it-automation/issues/3115)）

GitLab v19.5までに対応しました。特にv18以降のプロジェクト削除APIにおける「予定・恒久」削除オプションに対応済みです。\
GitLabのユーザーやトークンが存在しない、または無効になっている場合でも、作業実行時に自動で作成・再発行して処理を継続できるようになったため、Gitlabの切り替え時の作業コストを削減できるようになりました。


### 通信セキュリティの見直し（[#3109](https://github.com/exastro-suite/exastro-it-automation/issues/3109)）

Exastro本体からの外部通信に関連するセキュリティについて見直しました。
 - 認証局eMudhraの中間CA証明書で公開された証明書から秘密鍵を復元できる問題に対処しました。
 - 外部通信を行う各機能で、証明書の検証の有効・無効を切り替えられるようにしました。


### OASEのイベント受信の改善（[#3132](https://github.com/exastro-suite/exastro-it-automation/issues/3132)）

同じ取得日時（fetched_time）のイベントを、複数のリクエストで同時に受信できるようにしました。\
イベント駆動でイベントをAPIから送信する場合など、同じ取得日時で複数のリクエストが行われても、イベントを取り込めます。


## バグ対応

### AIアシスタントの「思考中」表示が残る不具合の修正（[#3123](https://github.com/exastro-suite/exastro-it-automation/issues/3123)）

AIアシスタントとの会話中、AIの応答に画面へ表示する内容がないと「思考中」の表示が残り、処理が止まっているように見える問題を修正しました。

### オペレーション名が8進数として扱われる不具合の修正（[#3131](https://github.com/exastro-suite/exastro-it-automation/issues/3131)）

オペレーション名に、0から始まる数値を設定してPlaybookで予約変数 \_\_operation_name\_\_ を使うと、8進数として扱われ、設定した値と異なる値でAnsibleが実行される問題を修正しました。\
ユーザが設定した値のまま、Ansibleに渡されます。
